# 直肠癌 MRI 报告结构化设计

## 目标

使用 LangChain 调用 OpenAI 兼容接口的 `gpt-5.4` 模型，对工作簿中 225 条中文直肠 MRI 报告逐行提取 7 个关键特征，并将结果追加到原始表格右侧。原始 `patient_id` 和 `Report` 两列不得修改。

## 输入与输出

输入文件：`副本直肠癌多中心文本.xlsx`

输入工作表：`Sheet1`

输入列：

- `patient_id`：病例标识。
- `Report`：中文 MRI 报告原文。

追加列及顺序：

1. `肿瘤的位置`
2. `肿瘤累及长度`
3. `肿瘤浸润深度`
4. `直肠系膜内淋巴结评估`
5. `直肠系膜外淋巴结评估`
6. `CRM受累情况`
7. `EMVI受累情况`

所有输出均为扁平字符串。无法从原文严格判断时写入字符串 `None`。

## 字段约束

### 肿瘤的位置

只允许：`上段`、`中段`、`下段`、`中上段`、`中下段`、`直肠全段`、`直肠乙状结肠交界区`、`None`。

### 肿瘤累及长度

输出单位统一为 mm，格式为数值加 `mm`，例如 `60mm`。原文为 cm 时乘以 10；原文未提供累及长度时输出 `None`。不得用最大厚度、横径或距肛缘距离替代累及长度。

### 肿瘤浸润深度

只允许：`T1`、`T2`、`T3`、`T4`、`None`。

- `T1`：累及黏膜或黏膜下层。
- `T2`：累及肌层但未突破，周围系膜脂肪间隙清楚。
- `T3`：肌层中断或穿透肌层侵犯直肠周围系膜脂肪，或穿透肌层侵犯内外括约肌间隙，或直肠周围脂肪间隙毛糙。
- `T4`：侵及邻近浆膜或腹膜返折，或侵犯膀胱、前列腺、精囊腺、子宫、阴道、外括约肌、肛提肌。

当报告直接给出分期且与描述无明显冲突时可采用；否则严格依据上述定义判断。证据不足时输出 `None`。

### 直肠系膜内淋巴结评估

只允许：`有`、`无`、`None`。

- 短径小于 5mm：边界不清、形态不规则、信号不均匀同时存在时为 `有`。
- 短径 5-9mm：上述三个可疑特征中任意两个存在时为 `有`。
- 短径大于 9mm：为 `有`。
- 明确未见可疑或未见淋巴结：为 `无`。
- 有淋巴结但描述不足以满足或排除标准：为 `None`。

### 直肠系膜外淋巴结评估

只允许：`有`、`无`、`None`。

- 系膜外淋巴结短径大于等于 7mm：为 `有`。
- 明确未见系膜外淋巴结：为 `无`。
- 报告未描述，或描述了系膜外淋巴结但没有足够尺寸信息：为 `None`。

### CRM受累情况

只允许：`有`、`无`、`None`。

- 肿瘤或淋巴结距 MRF 小于等于 1mm：为 `有`。
- 肿瘤邻近 MRF 局部增厚：为 `有`。
- 肿瘤及淋巴结距 MRF 大于 1mm：为 `无`。
- 未提供足够距离或筋膜描述：为 `None`。

### EMVI受累情况

只允许：`有`、`无`、`None`。

- 邻近血管增粗、形态不规则，或血管内见异常肿瘤信号充盈：为 `有`。
- 邻近血管形态规则、信号均匀并有流空效应，或明确写明系膜内血管未见明显异常：为 `无`。
- 仅描述“血管增多”而未描述增粗、不规则或异常充盈时，不作为阳性证据；无其他证据则输出 `None`。

## 架构

实现分为四个独立单元：

1. 结构化模型：Pydantic 模型定义 7 个字段及枚举约束。
2. 报告解析器：LangChain `ChatOpenAI` 连接 `https://apinebula.com/v1`，使用 `gpt-5.4` 和结构化输出，将单条报告转换为模型对象。
3. 批处理器：逐行解析，处理重试、跳过已有结果、失败记录和进度保存。
4. 工作簿写回器：读取原始工作簿，在原表右侧追加 7 列并导出新文件，不覆盖源文件。

API 密钥只从 `OPENAI_API_KEY` 环境变量读取；基础地址从 `OPENAI_BASE_URL` 读取，默认值为 `https://apinebula.com/v1`。代码、测试、日志和结果文件均不得包含明文密钥。

## 数据流

1. 读取 `Sheet1` 的 `patient_id` 与 `Report`。
2. 对每个非空 `Report` 调用结构化解析器。
3. 校验模型输出的字段名、枚举值和长度格式。
4. 将合法结果写入对应行的 7 个新增列。
5. 单行失败时重试；最终失败则该行 7 个字段写 `None`，并记录不含报告全文的错误日志。
6. 定期保存检查点，重启时跳过已经完整生成 7 个字段的行。
7. 导出为独立结果文件，并检查行数、列顺序、原始列一致性和新增列合法值。

## 模型提示策略

系统提示采用用户给出的医学定义和输出限制，并额外明确：

- 只能依据当前报告原文，禁止推测或使用病例外知识补全。
- 只输出 7 个字段，不输出解释、证据或嵌套对象。
- 直接使用结构化输出接口，不依赖自由文本 JSON 的标点格式。
- 对矛盾、模糊或证据不足的信息输出 `None`。

## 错误处理

- 网络超时、限流和临时服务错误使用有限次数指数退避重试。
- 结构化校验失败重新请求一次；仍失败则该行记为失败。
- 空报告不调用模型，7 个字段直接写 `None`。
- 输出文件使用临时文件完成写入后再替换目标文件，避免中断产生损坏工作簿。
- 失败日志只记录行号、`patient_id`、错误类型和简短错误信息，不记录完整临床报告或 API 密钥。

## 测试与验收

自动测试覆盖：长度单位换算、允许值校验、空报告、模型输出映射、重试、断点续跑、原始列不变和新增列顺序。

最终验收条件：

- 输出共 226 行，包含 1 行表头和 225 条病例。
- `patient_id` 与 `Report` 和源文件逐单元格一致。
- 7 个新增列位于原始两列之后，字段顺序正确。
- 所有分类值均属于各字段允许集合。
- 长度值仅为 `None` 或规范化的 `数字mm`。
- 工作簿能够正常打开，无明显截断或损坏。
